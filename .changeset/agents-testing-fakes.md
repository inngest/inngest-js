`inngest/experimental/agents/testing` fakes cover what real apps copied from the kit. `fakeSandbox()`: every sandbox has a `/work` of its own on the host that commands run against for real (a command, `cwd` or environment value that mentions `/work` and no entry of `commands` describes), snapshots keep a copy of it and a sandbox made from one starts with it, `diskPaths` lists more sandbox paths that live on the host (per sandbox), and `SANDBOX_WORK` is set for those commands. Processes started with `sandbox.processes.start` keep their output and can be waited for (`processes/<id>/wait`, `output`, `signals`); canned `commands` answer them like `exec`, and a process no entry describes exits 127 and says so. `startGitRemote({ token, repos, anonymousReads })` serves several seeded repositories (`repos: { website: files, source: { main: files, pr: files } }`, branches after `main` start from it; `uploadpack.allowAnySHA1InWant` is on), can allow fetches without the token (a push always needs it), and records the authorization of each push in `pushAuth`; `startGitRemote("token")` still gives one default repository. `fakeGitDataApi({ repo })` is the in-memory GitHub Git Data API (blobs, trees, commits and refs with real git hashes) to test a git-free push: pass its `fetch` and any `api` URL to the push options, `seed(repoDir, commit, ref)` loads a real commit as the remote's state, and `ref(name)` reads back the pushed branch. The `Symbol.asyncDispose` polyfill is one shared module now.
